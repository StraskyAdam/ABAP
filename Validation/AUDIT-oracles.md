# Fixture, Gateway and row-oracle audit

## Scope and evidence

Audited revision: `c2bf1b3cc171dfe043648d7294d58e9bee78cd45`. All line numbers below refer to that revision of `ABAP code/Unit test.txt`, not concurrent working-tree edits. Every source line in 5379–7187 was read, including all 31 complete method bodies. Declarations, substantive direct callers, parser/comparison dependencies after this range, and the corresponding production request/filter/count/order/output paths were inspected. Source initially matched the base; subsequent inspection used `git show` after concurrent edits appeared. No Unit test or production changes were made by this audit.

No SAP/Gateway/HANA runtime is available. No existing test suite was run, including on other agents' changes. `Validation/REPORT.md` was not used as evidence. Local JSON inspection is independent snapshot analysis, not an ABAP execution result. All 45 local JSON fixtures were verified against the base's ordinary blobs or Git LFS SHA-256 pointers before relying on their contents.

Verdicts distinguish **sound within contract**, **oracle defect**, **coverage limitation**, and **environment sensitivity**. A defect in a test oracle does not establish a defect in production. Snapshot/live data differences, configured user roles, exchange rates and current-date dependencies are environmental sensitivities, not implementation bugs.

## Declarations and production contract

- Test declarations 42–103: `ts_case` carries fixture, email/owner/flow/PSTYPE, range/raw filter, order, select, top-presence and count-presence flags. Expected rows are a **hashed unique** `(PONUMBER,ITEMNO)` table with JSON object offsets and a matched flag; JSON properties are hashed unique by name. Neither preserves row sequence. `mc_page_size=1000`, diagnostic sample limit 5000, MIME root `/SAP/PUBLIC/DAS/`.
- Helper declarations 424–665 correspond to all 31 methods in the matrix. `setup`, `reset_fixture`, dispatch, path/filter builders, quoting, raw HTTP and simple assertions have no declared checked exception. Parsing/fixture helpers generally declare `zcx_fi_das_error`; scope/paged execution also declares conversion and Open SQL errors. `get_gateway_response` defaults skip to zero. Filter contains and descending flags default false; key comparison defaults expected-match true. The first-property wrappers return a string even though named `rv_token`; the implementation returns **decoded text**, not a raw JSON token.
- Production interface `zif_fi_das_dashboard.txt` 1–96: Over=`1`, Under=`2`, Exclude=`3`; material=`0`, service=`9`, all=`*`; email is C(255), owner/PSTYPE C(1). - `ZCL_ZFI_DAS_DPC_EXT.txt` was read completely (1–223). `build_request` 57–68 requires a bound context. `get_parameter` 167–175 maps the exact `IP_EMAIL`, `IP_PSTYPE`, `IP_POOWNER` names. `get_filter` 99–140 obtains Gateway's complete Open SQL predicate and range projections; unsupported/untranslated nonempty expressions fail rather than silently becoming unfiltered. `get_orderby` 142–151 preserves requested field sequence and normalizes names/direction. `get_paging` 153–165 obtains top, skip and inline-count presence. The actual SAP `get_top()` signature/representation is not in this repository: its `IS NOT INITIAL` presence check alone is insufficient evidence of a `$top=0` bug.
- DPC flows 70–91, 177–221 invoke a **new** dashboard object, not test `mo_cut`, and wrap conversion, Open SQL and dashboard errors in `/iwbep/cx_mgw_tech_exception`. Gateway's metadata/URI validation can reject a request before these flows. The raw-helper unknown-order test therefore tests HTTP handling, not only production's tolerant private sort helper.
- `zcl_fi_das_dashboard.txt`: public adapters 992–1025 perform corresponding-field projection to generated MPC types. `execute_request` 1027–1071 validates, adjusts, obtains keys and builds rows; full processing applies the complete predicate, counts before paging, restores original paging, then sorts/slices. `adjust_request` 1073–1085 normalizes email and invokes extraction/default-sort/full-processing logic.
- `extract_filters` 2017–2111 clears stale AMDP filters. A nonempty complete predicate clears projected ranges and is retained unchanged; it is **not** intersected with projected key ranges. Without a complete predicate, ranges are converted either to keyed AMDP filters or a complete generic expression. `apply_generic_filter` 1276–1303 numbers input rows and invokes `filter_result` 2113–2125 (`APPLY_FILTER`, ordered by `original_row_index`); AMDP errors become dashboard errors.
- Key production 2680–3098 was read completely: owner/email and PSTYPE classification precede scope; current CSKS validity matters; PO totals/threshold classification precede item filtering; exclusion is flow-specific; count is computed before key paging; key order is PSTYPE descending, PONUMBER ascending, ITEMNO ascending. `get_required_keys` 3316–3346 supplies matching parameters. `get_access_scope` 2127–2144 uses wildcard scope for owners or percent-email, otherwise user roles.
- `apply_sort_and_paging` 1359–1435 ignores invalid/repeated private sort fields, appends default tie-breakers, sorts original typed values, and then applies skip/top, including explicitly requested zero. `get_default_orderby` 3823–3830 is the three-field default above. `get_inline_count` 2653–2659 emits a numeric string only when requested. `remove_default_sorting`/`set_full_processing` 3752–3777 preserve this optimization. `validate_request` 3779–3821 rejects invalid flow, empty email, owner/PSTYPE and negative paging.
- `get_odata_row` 3228–3293 maps actual calculated output, supplier ALPHA formatting, reviewer spelling `REVIWED_BY`, monetary formatting and mode-specific flags. `get_results` 3348–3375 retains key order while creating rows. The internal `original_row_index` exists in `ts_odata_result` (267–276), not the public result contract. SEGW metadata defines the two nonnullable string keys and the audited fields' string/decimal/date/time types.
- `zcx_fi_das_error.txt` was read completely: it is a `cx_static_check`; constructor stores `reason` separately and delegates `previous`. Dispatch logs inherited `get_text()`, not explicitly `reason`, so custom helper reasons are not guaranteed to appear in that diagnostic.

- Invalid-order error body2455–2501 bypasses checked GET intentionally: expects HTTP400, `"error"` substring, no “SHORT DUMP”, nonempty status text. The substring check alone is not full OData error-schema validation, and does not distinguish an intended bad-order400 from an unrelated400. No runtime result is assumed.

F (`assert_all_rows_match_filter`) callers are filter-sort paging; all six live value-help leaves; all-PSTYPE; company, description, currency/company, supplier ID, PO-OR/supplier-AND. Their positive first-page checks are normally nonempty. The helper still cannot establish complete membership, and the second paging page may be intentionally empty.

S (`assert_rows_sorted`) callers are filter-sort paging, PSTYPE asc/desc/pages, AMOUNTACCRUED and REVIWED_BY. The last two only require `count >= returned_rows`; empty/missing-count/empty-results payloads can satisfy those leaves without exercising ordering. PSTYPE first-value/boundary reads force actual rows, but do not guarantee multiple distinct values in an inspected page.

## Complex and cross-OR oracle independence

`matches_complex_fixture` requires PONUMBER, ITEMNO, POLINEDESC, POCREATEDAT, SUPPLIERNAME properties; assertion failure precedes unsafe missing-table dereference in grouped mode. A NULL operand returns false. For this complete conjunction that matches SQL WHERE acceptance: a NULL description/date/supplier cannot make the remaining AND expression true. All current service-snapshot supplier names are non-null.

The oracle independently decodes snapshot text and evaluates:

1. no lowercase `b` in description;
2. no `5` in PO;
3. lowercase `a` in description;
4. epoch milliseconds strictly greater than **1760400000000**, exactly **2025-10-14T00:00:00Z**;
5. case-sensitive supplier starts uppercase B OR contains uppercase A;
6. the exact PO string OR group from URI;
7. item00001 OR00003 OR00004.

It calls no dashboard extraction/filter/calculation routine. PO remains string, not NUMC/numeric, which matters. Its date regex requires a nonnegative unoffset `/Date(milliseconds)/` representation; that is a snapshot-format restriction, not generalized OData date support.

Independent base-snapshot result: **1674 positive rows**. Dropping each effective clause yields additional rows: no-description-b489; no-PO-5 1176; description-a638; date776; supplier1512; item688. Replacing date `>` with `>=` adds **3 otherwise-matching cutoff rows**, so exclusivity is discriminating.

**The complete PO OR group is tautological for lexical strings.** In particular `'9000600000' < '977'`, so `po <= '977' OR po > '9000600000'` already covers all string values. Removing that entire OR group yields the identical result, and no negative witness for the complete group can exist. All1674 selected fixture rows satisfy the first branch; the numeric reinterpretation of the group retains0. This is a correct oracle for the deliberately supplied expression, **not a production bug or a false numeric oracle**. To test individual PO branches, add separate non-tautological expressions; do not “repair” this requested predicate.

Cross-OR uses independent exact string key comparison and case-sensitive Fuji search. Expected **27 rows**: **19 supplier-only**, **8 both**, **0 PO-only**. The explicit witness assertion proves a projected PO-only prefilter loses expected rows. It does **not** prove the PO arm is evaluated: a supplier-only implementation returns the same27 rows (D9). Exact JSON parity/count still checks all selected rows, not merely one witness. This is a fixture-discrimination gap, not evidence that current production drops the arm.

## Confirmed defects and surgical patch proposals

These are source-proven test/helper failures or omissions; none asserts an observed production regression. Patches are proposals only.

### D1 — Requested missing inline count is accepted as zero

Evidence:5853–5868 returns initial0 when literal count absent;5591–5612 requests/parses count, without presence assertion. For any of the fifteen empty scope snapshots, `{"d":{"results":[]}}` with HTTP200 is indistinguishable from correct `__count:"0"`: parity sees0 expected rows,0 actual rows,0 count, and zero differences. The nonexistent-supplier leaf has the same gap. Missing count on nonempty parity normally fails by cardinality, so this is not a claim that all count failures are hidden.

**Patch:** require exactly one scalar `d.__count` when requested, reject absent/nonnegative-noninteger/malformed count, and only then convert. If retaining the light parser, add a presence assertion before conversion plus structural scoping; never let absence default to0 in required mode. Keep no-count mode's explicit absence assertion. Add absent-count vs valid-zero synthetic payload assertions.

### D2 — Duplicate-key logging is not asserted by index-only consumers

Evidence:6506–6515 logs duplicate, retaining first key.6180–6208 checks only page-to-page intersections. Its four callers1849–1922,2076–2126,2128–2190,2192–2254 never assert accumulated differences. Pages with repeated keys internally and disjoint unique keys across pages satisfy the cross-page helper. The Under/Exclude page-size100 checks count objects, not unique keys, so100 objects containing duplicates can pass. `test_empty_contains_po`5235–5309 likewise compares duplicate-collapsed key sets/counts without asserting differences.

**Patch:** make duplicate index insertion fail/raise immediately, or assert index cardinality equals raw object count within the duplicate helper and add a final log assertion to every index-only leaf. Immediate fail is simplest but retain accumulated diagnostics for parity if desired via an explicit strictness flag. Add repeated-key within page1, within page2 and across-page examples.

### D3 — Case-sensitive membership assertion erases case

Evidence:5970 and6000–6009 uppercase both values and use case-insensitive ABAP CS. A supplier response `fuji` is accepted against requested case-sensitive `substringof('Fuji',SUPPLIERNAME)`; description `local support` is accepted for `Local Support`. Production generic `APPLY_FILTER` retains exact supplied predicate; typed filter tests explicitly demonstrate case-sensitive default CP/EQ behavior.

**Patch:** compare original decoded text by default. For contains use `find(... case=abap_true)>=0`; add a deliberate case-insensitive flag only for tests that explicitly request UPPER-based semantics. Assert property exists and return/continue after recorded missing-property failure to avoid cascading exceptions. Add case-only negative witness.

### D4 — Missing ordering property silently becomes initial value

Evidence:6802–6811 returns empty when property absent;6028–6178 interprets empty as0/empty. A multirow response with missing AMOUNTACCRUED on every row is “sorted”; the amount/reviewer leaves need only `count>=rows`, so they can accept it. An empty response with missing count also satisfies those two leaves.

**Patch:** separate required-property lookup from optional lookup, or raise on absent field in `read_result_property`. Require at least two prepared rows with different sort values in sort tests; do not require nonempty in legitimate expected-empty tests. Assert count presence with D1. Verify both order direction and exact expected keys.

### D5 — Ordering values are JSON-decoded twice

Evidence:6810 already calls `unquote_json`;6064–6066 calls it again. For valid supplier names whose actual text begins/ends with quotes, literal quote characters are removed. For example decoded names `"Z"` and `A` are ascending by original character values (quote before A), but the helper transforms first name into Z and wrongly reports descending. Conversely a wrong sequence may be accepted after that transformation.

**Patch:** remove second `unquote_json` from sorted-row assertion; make raw-token/decoded-text APIs explicit in names. Keep null handling based on raw token/type before decode, not on string value `NULL`. Remove leading-space trimming if the contract is typed ABAP character sort. Add quoted-name and leading-space sorting witnesses.

### D6 — Aggregate normalization loses JSON token type

Evidence:7098–7120 decodes both tokens without requiring quoted strings, unlike7149–7152's guarded ordinary-string branch. For any unordered aggregate field, raw `null` vs string `"null"` compares equal; numeric `1` vs string `"1"` also compares equal. This bypasses the documented field-specific NULL allowlist and the claim that nonstring JSON tokens remain strict.

**Patch:** after approved NULL mapping, enter aggregate comparison only when **both** tokens are JSON strings; otherwise compare raw token/type strictly. Add null vs `"null"` and number vs same-text string negative tests, plus positive reorder/multiplicity/empty-slot cases.

### D7 — Sequential escape replacement is not a correct JSON decoder

Evidence:8090–8205 replaces Unicode/text escapes before doubled backslashes. Valid raw JSON strings `"\\u0026"` (literal backslash-u0026) and `"\\&"` (literal backslash-ampersand) both become backslash-ampersand in this helper, although their JSON-decoded values differ. Unhandled valid Unicode/control escapes can conversely false-reject semantically equivalent serialized strings.

**Patch:** decode strings in a single escape-aware pass or use an already-available SAP JSON string decoder verified on the target release. Decode each escape only once, preserve escaped literal backslashes, support all JSON escapes/Unicode including surrogate pairs, and reject invalid escape sequences. Test literal backslash-u/n/t separately from escaped character values. This affects property names, keys, selectors, ordinary comparison and aggregate comparison.

### D8 — CP converter accepts patterns it cannot faithfully translate

Evidence:5740–5748 removes any leading/trailing stars and then merely rejects remaining wildcard symbols. Thus accepted `Fuji*`, `*Fuji`, and `Fuji` all become `substringof('Fuji',property)`, not prefix/suffix/exact matching. Only current `*Fuji*` caller is correct.

**Patch:** either reject every pattern outside documented contains shape (`*literal*`, with explicitly handled all-stars empty case), or implement exact/prefix/suffix/contains translations based on original wildcard placement before stripping. Do not broaden this helper into unsupported date/numeric literal conversion. Add each accepted shape's negative witness.

### D9 — Cross-OR fixture cannot discriminate loss of the PO arm

Evidence: base fixture independent evaluation yields27 correct rows, but all8 PO8000401022 rows contain Fuji. Supplier-only result is identical; existing19 outside-PO witnesses discriminate only against a projected PO-only prefilter.

**Patch:** choose and preassert a PO arm having at least one non-Fuji row in this snapshot, or provision a dedicated stable fixture with PO-only, supplier-only, both and neither rows. Derive expected complete OR independently and assert both exclusive arms exist before requests. Do not label snapshot membership as an implementation defect or replace expected output with a production-generated baseline.

## Coverage and environmental limitations, not production defects

- **C1 — Set parity is not page/order parity.** Swapping unique correct rows within/across pages preserves all hash lookups, full property values and total count. `run_paged_case` does not compare expected page membership or page order and skips by actual page cardinality, not fixed requested size. Production contract has a deterministic default order and tie-breakers, so add an independently sorted expected key sequence (contract order, not downloader's incidental order), compare exact page slices and boundary/tie keys, and issue a final expected-empty request after N rows. Do not report current production ordering wrong solely because this oracle is insensitive. The exclusion positional test and synthetic typed paging tests provide partial separate coverage.
- **C2 — Live versus snapshot sensitivity.** MIME deployment, synchronized role users01…30, source rows/exclusions/history, exchange rates, configured thresholds, date cutoffs and CSKS current-date validity must match the XSA acquisition context. The downloader assembles all pages but does not explicitly request a deterministic `$orderby`; snapshot sequence itself is not an order oracle. Changes between requests can legitimately alter count/membership. No blanket nonempty assertion should be added to intentionally empty scopes.
- **C3 — Lightweight scanner is not full JSON/schema validation.** Both actual and expected inputs share scanners; malformed separators, wrong/nested envelope properties or extra invalid tails may be accepted. Ordinary expected/actual token comparison can then agree on invalid text. Add structural validation/scoped lookup before comparison if strict serialized-contract validation is claimed, while retaining bounded-memory comparison. Actual normal Gateway payloads are assumed valid; no malformed actual response was observed.
- Full raw-row comparison intentionally ignores metadata, permits missing ID, maps limited NULLs, canonicalizes time component padding, and treats listed aggregate fields as independent multisets. These are **declared compatibility rules**, not raw byte equality. Cross-field account-assignment tuple rearrangements are not discriminated under the temporary independent-field exception; maintainers should explicitly decide whether that relaxation remains acceptable.
- HTTP-success/error assertions and inherited exception paths were inspected statically; SAP proxy behavior, conversion BOM behavior, exact Gateway filter translation and runtime assertion recording are not executed or certified here.
